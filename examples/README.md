# How this setup is used

Three real projects, anonymized. Same core (role agents, orchestrate/team-lead, precompact, gates before merge), different emphasis.

## SaaS web product

A multi-tenant web platform made of several services (Go, TypeScript, Python) in a superrepo of git submodules, each released by its own tag pipeline with a manual production deploy. This is where `team-lead`, `pre-prod-check`, `full-audit`, `frontend-visual-audit`, `commit-push`, `release-tag`, `update-docs` and `gitlab-deploy` come from. The main problems were shared-resource collisions (several agents and other sessions in one checkout, one dev server, one browser) and false greens: a local gate that checked less than CI, test suites that skipped their whole body and still counted as coverage, a deploy job shown as "skipped" that looked like "waiting". Most of the rules in those skills are a direct response to an incident of that kind. Audits fan out dozens of read-only agents that write findings to disk, then skeptic agents try to refute every severe finding before a human picks what gets fixed.

## Roblox game

A phone-first multiplayer game built with Rojo and Luau, tested with Lune unit tests and in Roblox Studio through its MCP server. This project shaped the role definitions most: strict file slices per run, 12-line final messages with details in report files, the fixer's round limit with escalation to a stronger model, the analyst running a deterministic economy simulation over the real config modules, and the split between `designer` (owns and sees the look) and `visual-reviewer` (advisory, captures independently). Studio-specific procedures (own window per task, mute before Play, capture to files and check frames by numbers) are in `roblox-studio-capture/` as an example of an environment-specific skill.

## Generative-media pipeline

A local image/video generation pipeline (node-graph workflows, model fine-tuning configs, Python tooling, a SQLite ledger) that produces content under strict rules: licence restrictions on models, mandatory AI disclosure, platform-specific content limits, provenance for every published file. Here the orchestrator runs a fixed chain (research -> architect -> developer/designer/writer -> tester -> reviewer with veto) and every worker returns `blocked:` items instead of asking. The two hooks in `hooks/` come from this project: one protects datasets, archives and model weights from deletion or overwrite and keeps `.env` out of the conversation; the other runs a banned-words checker on every user-facing file the moment it is written. `compliance-review` is the generalized form of its publishing gate. Later work on this project added the paid-run discipline now in `orchestrate` (recipe card, pilot, two caps, spend and verdict ledgers, at most two paid runs per hypothesis), the `prompt-writer` role, and the status loop `analyst-report` -> `business-analyst-review`, where a strong-model analyst reviews the packed report under the same information boundary an outside analyst would have.

## Pattern: spec-first media generation

The same project produces short videos with a skill I keep private because it is tied to its content and tools; the pattern is general. One intake question batch fixes the taste calls up front. A timeline agent runs first and fixes shot ids and timecodes. Then parallel spec agents each own one dimension (each character's look and wardrobe per shot, environment, action and blocking, camera and light, optionally sound), an integrator merges them into a machine-readable shot list plus a list of conflicts, and an adversarial critic tries to break the shot list before any money is spent. Only then does a renderer turn the list into keyframes and clips, starting with a pilot of one shot. Automated post-gates (face similarity, audio checks that trim generator artifacts at the end of a clip) run before anything reaches the owner, and the owner judges a package, not a stream of files. The point is that the generators execute a spec and have no room to improvise.
